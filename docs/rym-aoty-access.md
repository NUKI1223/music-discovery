# Проверка доступа к RYM и Album of the Year

Первичная проверка: **2026-10-28**. Ниже сохранены её результаты: на том этапе данные сторонних выгрузок не скачивались. В последующей проверке **реально скачаны и нормализованы 5 000 строк RYM и 6 703 строки AOTY из публичных GitHub-файлов**, а неофициальный AOTY API вернул один настоящий cached ответ. Актуальное состояние — [полученные данные](community-data.md). Подтверждённой открытой лицензии на эти снимки нет; локальное исследование публичных файлов не объявляется правом их распространения.

## Вывод первичной проверки официального доступа

**Подтверждённого способа сейчас автоматически получить каталог, жанры и общественные рейтинги RYM/AOTY без аккаунта/ключа и с установленными условиями использования не найдено.** Это результат конкретной проверки, а не доказательство отсутствия любых частных договорённостей или будущего API.

| Путь | Техническое состояние | Решение проекта |
|---|---|---|
| AOTY: официальный API/data partnership | Официальные условия предлагают обращаться за API-доступом; открытого документированного self-service контракта не найдено | `permission_required`, не включать сборщик |
| AOTY: собственные оценки CSV | Официально существует с 22.04.2026; settings без входа направляет на страницу регистрации | Возможен будущий личный импорт; пользователь пока не имеет профиля |
| RYM: публичный API | Домен `api.sonemic.com` отвечает текстовой заглушкой; рабочий контракт, квоты и условия не подтверждены | `unverified`, не выдавать за действующий API |
| RYM: собственный экспорт | Найдены описания импорта чужими приложениями; актуальный официальный интерфейс в этой проверке недоступен | `unverified_personal_export`; не заменяет общественный каталог |
| Сторонние Kaggle CSV | Файлы описаны, но лицензии неизвестны или источник полномочий на выдачу лицензии не подтверждён | Не включать в распространяемый каталог |
| Unofficial AOTY API | Авторы прямо описывают HTML scraping | Наличие публичного endpoint не подтверждает разрешение владельца данных |

## Реализованные HTML-парсеры

По запросу пользователя добавлены парсеры RYM/AOTY, CLI обработки сохранённого HTML и ограниченный загрузчик одной страницы. Прямой живой сбор не подтверждён: RYM robots запрещает запросы клиента, AOTY robots вернул 403. [Команды и формат результата](web-parsers.md), [проверка доступа](parser-access.md). HTML-тесты используют синтетические страницы; позднее реальные данные получены другим путём — через опубликованные GitHub-снимки, описанные выше.

## AOTY: первичные подтверждения

[Terms of Use](https://www.albumoftheyear.org/terms-of-use/) помечены обновлением 25.02.2026. Разделы 2, 4 и 9 ограничивают автоматизированный доступ и систематическое составление базы; §9 направляет заинтересованных в API или data partnership к владельцам. В текущем документе не обнаружено общей открытой лицензии на базу общественных рейтингов. Это основание не активировать автоматический импорт без дополнительных условий; публичность страницы сама по себе их не устанавливает.

В [официальном changelog](https://www.albumoftheyear.org/changelog/) запись **22.04.2026 — Export Ratings** подтверждает CSV собственных оценок из settings. Переход по официальной ссылке [settings](https://www.albumoftheyear.org/account/edit.php) в незалогиненном состоянии привёл к [странице входа](https://www.albumoftheyear.org/account/). Личный экспорт не является выгрузкой всех общественных оценок и counts. Создание пустого профиля сейчас не даст уже накопленную личную историю.

[Документация community API](https://aoty.prigoana.com/redoc) и [репозиторий его автора](https://github.com/edideaur/AOTY-api) называют сервис неофициальным и описывают извлечение HTML. Никакие album/search endpoints этого сервиса в проверке не вызывались. Лицензия клиентского кода не считается лицензией на исходные рейтинги.

## RYM/Sonemic: что подтверждено, а что нет

[api.sonemic.com](https://api.sonemic.com/) доступен без ключа, но вернул только короткое указание прочитать документацию, без ссылки, схемы API или данных. Сам HTTP-ответ не подтверждает ни поддержку чтения релизов, ни право на массовое использование.

Официальные страницы [Terms of Service](https://rateyourmusic.com/tos), [FAQ](https://rateyourmusic.com/wiki/RYM:FAQ) и [RYM Webservice/API issue](https://rateyourmusic.com/rymzilla/view?id=683) не удалось прочитать данным браузером; для `/tos` инструмент явно сообщил запрет robots.txt. Обход не выполнялся. Поэтому точную актуальную редакцию RYM ToS здесь не цитируем и не утверждаем, что проверили её текст.

[Record Club](https://record.club/help/import) документирует собственный импорт RYM CSV: релизы, личные оценки и обзоры; сопоставление происходит по артисту, названию и году. Это первичный источник о возможностях **Record Club**, но вторичное свидетельство о текущем интерфейсе RYM. Он не подтверждает наличие открытого RYM catalog API или разрешения на сбор community ratings. Пользователь проекта пока не имеет такого CSV.

## Проверенные сторонние наборы

Карточки проверены также через публичный metadata endpoint Kaggle `https://www.kaggle.com/api/v1/datasets/view/<owner>/<slug>`, поскольку веб-страницы некоторых наборов отдавали браузеру пустой документ. Это были запросы **описаний и лицензий**, не скачивание CSV. Размеры ниже — поля метаданных издателя, не результат проверки содержимого файлов.

| Набор / дата обновления | Заявленное содержимое | Заявленная лицензия и проблема |
|---|---|---|
| [tobennao/rym-top-5000](https://www.kaggle.com/datasets/tobennao/rym-top-5000), 14.03.2022 | 5 000 наиболее обсуждаемых альбомов; raw/clean CSV; около 6.02 MB по view API. Названия, артисты, дата, жанры, descriptors, средняя оценка, counts | `Unknown`. Автор описывает извлечение 125 страниц Custom Charts; подтверждения разрешения на распространение исходных данных нет |
| [gabepy/rym-top-5000-albums-expanded](https://www.kaggle.com/datasets/gabepy/rym-top-5000-albums-expanded), 25.03.2026 | Расширение предыдущей выборки: artist IDs, тип/дата, родительские жанры, группы descriptors; около 3.12 MB | `Unknown`. Ссылается на прежний notebook/набор; новая дата публикации не подтверждает свежесть исходных голосов |
| [tabibyte/aoty-5000-highest-user-rated-albums](https://www.kaggle.com/datasets/tabibyte/aoty-5000-highest-user-rated-albums), 20.10.2024 | По описанию 5 000 top-rated альбомов: артист, название, дата, жанры, score, число оценок; около 0.875 MB | Badge: **CC BY 3.0**; текст описания утверждает **CC BY-NC-SA 3.0** от AOTY. Это внутреннее противоречие. Первичный grant, его дата и применимость к этим полям не представлены |
| [matteodelseppia/album-of-the-year-best-albums-1965-2025](https://www.kaggle.com/datasets/matteodelseppia/album-of-the-year-best-albums-1965-2025), 13.04.2025 | Артист, title, rating, release_date, genres, cover_url, AOTY link, must, num_ratings, year, rating_type; около 13.11 MB. Число строк в проверке не подтверждено | Badge: **MIT**. Описание перечисляет поля, но не подтверждает полномочия загрузившего на лицензирование исходной AOTY-базы |

Решение по всем четырём: **`license/provenance_unverified`**. Не объявляем наборы незаконными; не считаем бейдж uploader доказательством прав источника. Для tabibyte отдельно нужна проверка исторического первичного grant: текущая редакция ToS сама по себе не доказывает, что ранее выданной лицензии никогда не было.

Даже после подтверждения лицензии top-5000 выборки ограничены популярными/высоко оценёнными релизами и не доказывают покрытие малоизвестного хип-хопа. Старые counts нельзя выдавать за текущую известность: нужны реальные `observed_at`, раздельные source scales и анализ selection bias.

Публичный [HF metadata search по rateyourmusic](https://huggingface.co/api/datasets?search=rateyourmusic) и [по aoty](https://huggingface.co/api/datasets?search=aoty) вернул `[]` во время проверки. По короткому `rym` нашлись нерелевантные названия. Это ограниченный поиск по каталогу, не утверждение, что ни в одном HF-наборе никогда нет таких данных.

## Проверенная исследовательская альтернатива

Статья [Zhang et al., PLOS ONE, 2018](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0206458) описывает RYM-граф: 3 378 пользователей, 4 489 объектов и 66 408 связей. Авторы заявляют соблюдение условий источников; статья опубликована открыто. Однако доступный список supporting information содержит PDF и EPS-рисунки, а не подтверждённую готовую таблицу релизов/жанров. Лицензия статьи не принимается как автоматическое разрешение на произвольную стороннюю RYM-выгрузку. Этот результат не даёт готового каталога для интеграции.

## Что можно сделать дальше

1. Сейчас продолжать на уже подтверждённых источниках метаданных; отсутствие RYM/AOTY counts сохранять как `null`. Не присваивать таким релизам доказанную малоизвестность.
2. Подготовить, но не отправлять без отдельного указания, запрос AOTY на read-only доступ к release IDs, жанрам, агрегированным scores/counts, датам наблюдения и ссылкам. Уточнить условия локального некоммерческого ML, хранения snapshots, обновления, атрибуции и распространения каталога. Персональные usernames/reviews для MVP не нужны.
3. Для RYM сначала получить актуальную официальную документацию API/экспорта и условия, а не строить зависимость на текстовой заглушке.
4. Если появится собственный экспорт пользователя, импортировать личные оценки отдельно от общественных сигналов после проверки формата и сопоставления релизов.
5. Если автор стороннего набора предоставит проверяемое разрешение или первичную лицензию, сначала зафиксировать grant/version, происхождение, дату сбора и покрытие; затем решать вопрос интеграции. До этого **готового разрешённого RYM/AOTY dataset для root-интеграции по результатам проверки нет**.

Файл фиксирует инженерное решение о подключении данных и пределы проверки; он не заменяет юридическое заключение о конкретном использовании.
