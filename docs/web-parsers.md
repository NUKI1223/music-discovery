# Парсеры RYM и Album of the Year

Реализованы два парсера сохранённого HTML и отдельный загрузчик одной страницы. Они не зависят от жанра: hip-hop остаётся первым пилотом. Совместимость с живой вёрсткой пока **не подтверждена**: RYM robots.txt запрещает запросы этого клиента, AOTY robots.txt вернул HTTP 403. [Результаты проверки доступа](parser-access.md).

## Что извлекается

| Поле | RYM | AOTY |
|---|---|---|
| Идентичность | URL, название, артисты, год | ID/URL, название, артисты, год |
| Жанры | Основные и дополнительные раздельно | Жанры источника |
| Пользовательская оценка | Исходная шкала 0–5 | Исходная шкала 0–100 |
| Число оценок | Точное целое при наличии | Точное целое при наличии |
| Критики | Не смешиваются с пользователями | Отдельная оценка и число обзоров |
| Происхождение | URL, время снимка, hash HTML, версия парсера, свидетельства полей | То же |

`25.3K` сохраняется исходным текстом, а точное число остаётся `null`. Количество текстовых пользовательских отзывов не подменяет количество оценок. Неоднозначные релизы, противоречащие URL и страницы защиты отклоняются. Поля неизвестного происхождения не дополняются догадками LLM.

## Проверить локально

Из корня проекта выполните пример на **синтетической**, явно маркированной странице:

```bash
uv run python -m discovery.catalog.web parse \
  --source aoty \
  --html tests/catalog/web/fixtures/aoty_synthetic_album.html \
  --url https://www.albumoftheyear.org/album/987654-synthetic-artist-test-release.php \
  --observed-at 2026-10-28T12:00:00+00:00 \
  --fixture \
  --output artifacts/parsers/aoty-fixture.json
```

Для собственного сохранённого HTML замените файл и URL, укажите **фактическое время получения страницы с часовым поясом** и уберите `--fixture`. Поддерживается UTF-8; максимальный размер входного файла — 5 MB. Выходной файл должен быть новым: существующий экспорт не перезаписывается. Время, указанное вручную, сохраняется как заявленное пользователем, а не независимо подтверждённое.

Сохранённый результат имеет `dataset_kind=unmatched_source_release`. Это отдельная запись источника: парсер не сопоставляет её автоматически с MusicBrainz и не превращает общественный рейтинг в личный лайк. Для использования в каталоге следующим этапом нужны проверенное сопоставление релизов, нормализация жанров и аудит покрытия. Флаг `live_parser_verified=false` сохраняется до проверки настоящих страниц; `--fixture` не является способом проверки живого сайта.

## Загрузчик

```bash
uv run python -m discovery.catalog.web fetch \
  --url https://rateyourmusic.com/release/album/death-grips/the-money-store/ \
  --output-dir data/captures
```

При текущем доступе ожидается остановка `ROBOTS_DENIED`, без обращения к странице релиза. Загрузчик проверяет robots, имеет ограничения частоты/размера/времени и останавливается на блокировках. Успешная загрузка сохраняет `page.html` и `provenance.json` в новой директории. Для последующего `parse` берите URL и `captured_at` из provenance. Массового обхода charts и автоматического обновления здесь пока нет.

## Проверки и границы

```bash
uv run pytest -q tests/catalog/web
```

Тестовые страницы написаны специально для проверок. Селекторы сверены с опубликованным кодом сторонних парсеров; это не заменяет живой снимок сайта. Проверки охватывают разделение user/critic, чужие счётчики и названия на странице, неоднозначный JSON-LD, округления, исходные шкалы, запрет перезаписи, robots/403/429, перенаправления и лимиты. Тесты не выполняют сетевых запросов.

Отдельным путём получены [реальные исторические выгрузки RYM/AOTY](community-data.md) через GitHub; они нормализуются модулем `discovery.catalog.community`, а не этим HTML-парсером. Каталог приложения остаётся на 520 релизах MusicBrainz с отдельным обогащением Wikidata. Совместимость HTML-парсеров с живыми страницами пока не подтверждена.
