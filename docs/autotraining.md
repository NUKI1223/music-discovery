# Локальный цикл экспериментального обучения

Цикл обучает существующую логистическую модель на явных оценках **«Прослушал — нравится / не нравится»** из одной выбранной базы. Он сохраняет экспериментальный артефакт, проверяет отложенные данные и сравнивает результат с базовой вероятностью и предыдущим кандидатом. Он **не включает модель на сайте** и не изменяет настройки сервера.

Word-сценарии и описания звучания — GOLD для проверки. Их оценки, ожидаемые исполнители и тексты описаний не становятся обучающими метками или признаками. Аудиофайлов для оценки звучания сейчас нет: отчёт не объявляет звучание или музыкальное качество проверенными.

## Запуск

Из корня проекта после `uv sync`:

```bash
uv run python -m discovery.training.autotrain \
  --db runtime/web/users/ACCOUNT_ID/discovery.sqlite3 \
  --catalog data/unified/community-vibes-v3/catalog.json \
  --output-dir runtime/training/ACCOUNT_ID \
  --once
```

`ACCOUNT_ID` — внутренний ID именно того аккаунта, чьи оценки нужно использовать. Команда требует существующую базу: отсутствие файла не создаёт пустую историю. Она не ищет другие аккаунты и не объединяет их данные. Каталог вывода привязывается к хешу абсолютного пути выбранной базы; попытка использовать его с другой базой отклоняется без изменения отчётов. Для другой базы нужен отдельный каталог вывода.

Для периодической проверки новых оценок:

```bash
uv run python -m discovery.training.autotrain \
  --db runtime/web/users/ACCOUNT_ID/discovery.sqlite3 \
  --catalog data/unified/community-vibes-v3/catalog.json \
  --output-dir runtime/training/ACCOUNT_ID \
  --watch --interval 300
```

Минимальный интервал — 60 секунд. `Ctrl+C` останавливает цикл. Сервис автоматически не устанавливается и не включается. Без изменения входных данных повторный запуск возвращает сохранённый отчёт с `skipped: true` и не обучает модель заново. Одновременный процесс для того же каталога получает `busy`.

Цикл не закреплён за одним жанром: обучение и сравнения выполняются отдельно для каждого жанра с достаточными данными. Покрытие текущего GOLD-пилота не означает проверки всех музыкальных жанров.

Для воспроизводимого исторического среза можно добавить `--cutoff 2026-11-01T00:00:00+05:00`. У cutoff должен быть часовой пояс. Поздние оценки и исправления после cutoff не используются. `--sound-gold` и `--cases-gold` позволяют явно выбрать другие файлы GOLD; для GOLD-сценариев нужны соответствующие сохранённые подтверждённые фильтры, иначе проверка получает `unavailable`, а не фиктивный успех.

Дата GOLD-проверки берётся из фиксированного `as_of` файла подтверждённых входов и не меняется каждый день. Можно явно задать `--evaluation-as-of YYYY-MM-DD`; дата входит в хеш конфигурации. Она независима от cutoff обучающих оценок.

## Защита данных и отсутствие утечек

Исходная SQLite-база открывается только для чтения. На время одного запуска создаётся согласованный снимок SQLite в приватном каталоге; после извлечения данных он удаляется. В экспериментальных файлах остаются только данные обучения и отчёты, а не копия переписки или парольная база. Каталог вывода имеет права `0700`.

Новые решения используют `genre-tags-v2-artist-frequency`. Цикл по умолчанию выбирает эту версию; старые строки сохраняются в истории и перечисляются в `exclusions.feature_version_excluded_rows` и `feature_version_excluded_release_ids`, но не смешиваются с новыми признаками. При недостатке новых оценок возвращается `insufficient_data`. Исторический расчёт v1 и старые конфигурации остаются для явного воспроизведения. Для низкоуровневого обучения согласованного экспорта v2 доступен `configs/supervised-artist-frequency.json`.

Используются признаки, сохранённые при исходной рекомендации. Они не пересчитываются с сегодняшним вкусом или новыми оценками. Исправления оценок разрешаются существующим `training_records` на выбранный cutoff. «Уже знаю», «Послушать позже», «Прослушал — смешанно», балл, рецензия, свободный текст и отсутствие оценки не становятся метками. Более поздняя смешанная оценка снимает прежнюю метку релиза.

Перед обучением исключаются:

- все GOLD-релизы;
- все релизы защищённых GOLD-исполнителей, включая другие альбомы;
- совпадения, найденные по старым каталогам решений, даже если ID исполнителя, название или связи источников позднее изменились;
- релизы, которых нет в выбранном каталоге.

Для каждого исторического каталога строится отдельный GOLD-манифест; их объединение и хеши сохраняются. История с демонстрационным происхождением получает `fixture_rejected`; её нельзя превратить в персональное обучение удалением защищённых строк.

## Обучение и проверки

Используется существующий `training.pipeline.train` с фиксированным seed (по умолчанию 17). Жанр должен иметь как минимум 60 явных оценок, в том числе не менее 15 каждого класса. Это минимальный порог обучения, а не достаточное доказательство качества.

Разделение по времени: первые 60% — обучение, следующие 20% — валидация, последние 20% — тест. Метка должна быть доступна к границе соответствующей исторической части. ID релиза не может пересекать части. Проверяются также строгий порядок времён решений и доступности меток между частями; совпадение на временной границе блокирует статистический допуск.

Для каждого обученного жанра тест содержит не менее 20 доступных оценок, в том числе не менее пяти каждого класса. При наличии предыдущего кандидата сравнение использует только релизы, которых не было в его обучении и которые рекомендованы **после его cutoff**. Старый тест не выдаётся повторно за новые независимые данные.

Отчёт измеряет log loss и Brier score:

- кандидат сравнивается с постоянной долей положительных меток в обучающей части соответствующего жанра;
- при наличии предыдущего кандидата оба оцениваются на одной свежей тестовой части;
- log loss должен строго улучшиться, Brier score не должен ухудшиться;
- проверяются охват жанров, число классов, отсутствие нарушений жанра и существующие правила `promote_artifact`;
- NaN, бесконечные вероятности, значения вне `[0, 1]` и несовпадение числа прогнозов и меток отклоняются.

Постоянная базовая вероятность — статистический baseline, а не доказательство превосходства над музыкальным подбором. Дополнительно запускается бесплатный GOLD replay с сохранёнными подтверждёнными фильтрами: сравниваются обычный ранжировщик и фактические коэффициенты кандидата в экспериментальном режиме. Он не делает новый вызов LLM и не объявляет прежние обсуждённые GOLD-примеры слепым тестом. Отсутствие подходящих сценариев, аудио или независимых оценок остаётся явно видимым.

Даже при `statistical_gate: passed` артефакт имеет `validated_genre_ids: []`, а `production_deployment` — `blocked`. Кандидат остаётся экспериментальным: успешная проверка вероятностей вкуса не заменяет проверку звучания, известности и музыкальных рекомендаций.

## Файлы и состояния

`latest.json` содержит последний отчёт. Возможные состояния: `insufficient_data`, `experimental`, `fixture_rejected`, `error`, `busy`. Недостаток данных и ошибки сохраняют предыдущие указатели артефактов. Ошибки записываются без содержимого приватной базы и секретов.

Каждый завершённый запуск хранится в `runs/<fingerprint>/`:

- `eligible-records.json` — фактические разрешённые обучающие строки;
- `gold-manifest.json` и `historical-gold-manifests.json` — карантин GOLD;
- `artifact.json` — кандидат, если данных хватило;
- `report.json` — происхождение, исключения, временные части, метрики и GOLD-результат.

Fingerprint включает данные и cutoff, каталог, GOLD и исторические манифесты, подтверждённые входы GOLD, исходный код извлечения/обучения/оценки, конфигурацию, версии численных зависимостей и идентификатор выбранной базы. Неизменные входы дают тот же артефакт. Смена данных, каталога, GOLD, кода или seed создаёт новый запуск.

`experimental_registry.json` — единственный авторитетный указатель на `current` и `previous`. `current` означает последний экспериментальный кандидат, **прошедший статистический гейт** (`statistical_gate == "passed"`), а не лучшую или действующую модель. Сначала полностью сохраняются файлы запуска, затем одной атомарной заменой меняется реестр. Если процесс остановится между этими шагами, повторный запуск завершит публикацию готового артефакта без повторного обучения.

Откат указателя:

```bash
uv run python -m discovery.training.autotrain \
  --db runtime/web/users/ACCOUNT_ID/discovery.sqlite3 \
  --catalog data/unified/community-vibes-v3/catalog.json \
  --output-dir runtime/training/ACCOUNT_ID \
  --rollback
```

Прогон с `statistical_gate == "blocked"` сохраняет артефакт и попадает в `candidate_run_ids`, но не становится `current` и не вытесняет `previous`. Откат возвращает только на прогон, ранее прошедший гейт (проверяется по `report.json`). Откат требует ту же базу аккаунта, меняет местами экспериментальные `current` и `previous` и не переобучает модель. Повторный запуск старых неизменных входов не отменяет намеренный откат. Ни обучение, ни откат не изменяют обслуживаемую сайтом модель.

## Проверка реализации

```bash
uv run pytest -q tests/training/test_autotrain.py
```

Тесты используют только синтетические контрактные записи во временных каталогах: полный цикл train/evaluate, воспроизводимость, идемпотентность, изменения входов, чтение исходной базы без записи, сохранение предыдущей модели при ошибках, запрет fixture и чужого аккаунта, cutoff, пересечения и временные границы, исторические GOLD-ID, свежий тест для предыдущей модели, восстановление публикации и откат.
