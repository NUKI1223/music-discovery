Иерархия — явная редакционная модель проекта. Для неоднозначных названий
проверены родительские области источника: Digicore относится к Hip-hop,
Trap Metal — к Trap/Hardcore Hip-hop, Witch House — к Electronic;
слово «metal»/«house» само по себе не устанавливает область.
Bare Trap всё ещё требует независимого хип-хоп контекста.
Старые имена/родители жанров сохраняются ради совместимости; это не полная
копия иерархии AOTY (например, Minimal Synth сохраняет старую связь).

## Воспроизводимость и данные

Таксономия: `community-taxonomy-v2+975073b40a21`.
Снимок: `community-unified-f89dbca2dd28372f`.
SHA-256: `3e9df7a2490ee9eb781736568b7a974eede67e52deb823cfe88f6b2ab16cda60`.

`src/discovery/catalog/remap.py` создаёт копию и переиндексирует только
производные поля сопоставления. Сохраняются все прежние ID, названия,
исполнители, даты, ссылки, наблюдения, исходные метки, порядок Vibe и
доказательства получения данных. Старый файл каталога не меняется.
Аудит проверил 64 243 прежних строки метаданных. Повторная переиндексация
идемпотентна; первичные метки добавляют допуск, вторичные — только контекст.

Воспроизведение в **новом**, ещё не существующем каталоге:

```bash
.venv/bin/python scripts/expand_source_genres.py \
  --base data/unified/community-vibes-v3/catalog.json \
  --dataset data/community/aoty-genre-expansion-20261103 \
  --output-dir /tmp/music-genres-rebuild
```

`remapping.json` объясняет добавленные привязки каждого релиза,
`taxonomy.json` — остаток нераспознанных меток, `matching.json` — решение
об идентичности новых альбомов. При добавлении новых источников неоднозначные
совпадения остаются в `pending.jsonl`, а не попадают автоматически в выдачу.

Новый конфиг обучения: `configs/supervised-genres-v4.json`.
Признаки сохраняют `genre-tags-v2-artist-frequency`, ранжировщик —
`baseline-v4-vibe-order`. Старые модели с другой версией таксономии
не применяются; исторические обучающие данные не переименованы в новую
версию. Переобучение и платные вызовы в этой задаче не выполнялись.
