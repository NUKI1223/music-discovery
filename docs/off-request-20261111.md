# Кнопка «Не по запросу»

Дата: 2026-11-11. Код: `src/discovery/contracts/__init__.py` (`Feedback`),
`src/discovery/web/schemas.py` (`FeedbackRequest`, `ReleaseCard`, проверка `listened_only`),
`src/discovery/storage.py` (`Store.off_request_release_ids`),
`src/discovery/web/chat.py` (`get_chat`, `handle_message`), `frontend/src/ReleaseCard.tsx`.

## Что добавлено

Шестая кнопка на карточке релиза: «Не по запросу» (вид оценки `off_request`).
Она означает, что альбом не соответствует тому, что человек просил в этом запросе.
Это не оценка вкуса: кнопка не говорит, нравится ли альбом.

## Чего кнопка не делает

- Не отмечает альбом прослушанным и не ставит пометку «В прослушанных».
- Не добавляет альбом в «Мою коллекцию».
- Не делает исполнителя знакомым.
- Не меняет профиль вкуса: любимые и нелюбимые релизы по жанрам остаются прежними.
- Не создаёт обучающую метку. Функция `training_records` (`src/discovery/cli.py`)
  такие события не берёт, и прежняя метка от этого не меняется.
- Не влияет на награды экспериментального бандита (`_reward_scores` в `src/discovery/service.py`)
  и на метрики (`discovery_metrics`).
- Балл и рецензию к этой отметке добавить нельзя: сервер отвечает 422.

## Как это влияет на подбор

Эффект только личный и работает только в чате сайта. `Store.off_request_release_ids`
возвращает альбомы, которые нужно исключить из новой подборки. `handle_message` в `chat.py`
добавляет их в `excluded_release_ids`.

Отметка запоминает контекст решения, в котором её поставили:

- жанр запроса (`genre_scope_id`);
- закреплённые поджанры (`locked_subgenre_ids`): поджанры, которые пользователь закрепил
  в запросе.

Альбом исключается, если жанр нового запроса тот же и выполнено одно из условий:

- отметка сделана без закреплённых поджанров, тогда она действует на любой запрос этого жанра;
- в новом запросе есть закреплённые поджанры, и все они входят в поджанры отметки.

| Отметка сделана | Новый запрос | Альбом исключается? |
| --- | --- | --- |
| жанр A, без закреплённых поджанров | жанр A, поджанры не закреплены | да |
| жанр A, поджанры s1 и s2 | жанр A, закреплён s2 | да |
| жанр A, поджанры s1 и s2 | жанр A, закреплены s1 и s3 | нет |
| жанр A, любые поджанры | жанр B | нет |

## Как снимается отметка

Любая более поздняя оценка того же релиза видов «Уже знаю», «Послушать позже»,
«Прослушал — нравится», «Прослушал — смешанно» или «Прослушал — не нравится» снимает
все отметки «Не по запросу» этого релиза, для всех жанров. Отдельной кнопки отмены нет.
Виды `wrong_genre`, `not_now` и `familiarity` отметку не снимают. Сайт их не пишет;
`wrong_genre` и `familiarity` записывает только Streamlit.

## Карточка

Действует общее правило журнала: для карточки важно последнее событие по релизу целиком.
Поэтому после «Не по запросу» карточка не показывает балл и рецензию, даже если они были
раньше. Под кнопками появляется пояснение «Не по запросу · больше не предлагаем для этих жанров».
Оно короче точного правила: исключение касается жанра запроса и поджанров отметки.

В «Моей коллекции» отметка не показывается. Альбом остаётся там с прежним состоянием.

## Ограничения

- Отметка только личная. Если много людей отметят один альбом «не по запросу» для одного
  жанра, система пока не перестаёт предлагать его всем. Для такого правила нужен общий счётчик
  по паре «альбом + жанр» с порогом. Сейчас его нет: аккаунт один, базы аккаунтов раздельные.
- Исключение действует только в чате сайта. CLI, Streamlit, evals, `service.recommend`
  и ранжировщик отметку не читают.
- Вид `wrong_genre` пишет только Streamlit, его никто не читает. Он не менялся и с новой
  кнопкой не связан.
