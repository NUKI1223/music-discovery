# Проверка сопоставления релизов

`data/evals/entity-matching-gold.json` — замороженный **предварительный эталон,
просмотренный отдельным coding-agent**. Название файла `gold` не означает
независимую человеческую разметку: `human_review_complete=false`,
`labels_generated_by_matcher=false`. Метки были выбраны по исходным полям до
первого запуска `classify_pair`; результат matcher не используется для их создания.

В наборе 50 реальных пар из локальных исторических строк RYM/AOTY и MusicBrainz:
30 предполагаемых совпадений, 14 различных релизов, 6 неразрешённых пар. Это 38
различных исходных строк и 32 кандидата MB; повторяющиеся пары зависимы.
Отдельно находятся 6 искусственных ловушек с `is_fixture=true`, исходным кейсом
и явно записанными изменениями. Их результаты не добавляются к реальным метрикам.

Каждый кейс содержит исходную строку, неизменённого кандидата MB, основания метки,
имена исполнителей и наблюдаемый тип релиза. В реальных строках тип релиза RYM/AOTY
отсутствует: тип MB — одностороннее свидетельство, а не подтверждённое согласие
источников. Даты сравниваются в разрешении года MB; день/месяц исходной строки
сохранены, но не подтверждены MB. В частности, у The Money Store разные дни в
исторических RYM и AOTY при одинаковом годе. Время наблюдения рейтингов остаётся
`null`; сбор или просмотр эталона не делает исторические показатели свежими.

Явный alias `Kanye West → Ye` опирается на
`data/manifests/musicbrainz-expanded.json`, `acquisition.favorites` с MB artist ID.
Альтернативные названия и связи частей альбома не угадываются.

## Запуск без сети

Из корня проекта:

```bash
.venv/bin/python -m discovery.evals.entity_matching \
  --verify-source-root . \
  --output artifacts/evals/entity-matching.json
.venv/bin/pytest -q tests/catalog/test_entity_matching_eval.py
```

Без `--verify-source-root` replay использует встроенные неизменяемые снимки пар
и не требует крупных исходных файлов. С этим параметром дополнительно сверяются
SHA-256 четырёх исходных файлов. Хеш доказывает неизменность локальных байтов,
а не подлинность данных платформы. Изменившийся снимок вызывает явную ошибку;
не нужно автоматически перезаписывать метки под новые данные.

Отчёт фиксирует версию и SHA-256 эталона, версию и хеш кода matcher, хеш evaluator,
время запуска, ответы по кейсам и отдельные показатели для RYM/AOTY. Вызовы
OpenRouter и других сетевых сервисов отсутствуют.

## Что именно измеряется

| Показатель | Определение |
|---|---|
| Precision | TP / (TP + FP), только разрешённые положительные/отрицательные метки |
| Recall | TP / все положительные метки; отказ или abstain на положительной паре уменьшает recall |
| False merges | `match` на размеченной отрицательной паре |
| False merge rate | False merges / число размеченных отрицательных пар |
| Prediction abstain rate | Число ответов `abstain` / все пары данного раздела |
| Automatic match rate | Число ответов `match` / все пары данного раздела |
| Pending reference | Неустановленная идентичность, исключённая из бинарных метрик |
| Unsupported merges | `match` на pending reference; риск без достаточного основания, не доказанный false positive |

При пустом знаменателе показатель равен `null`, а не идеальным 100%.
`reject` на неразрешённой паре не считается доказанным true negative.
`abstain` безопасен для проверки объединений, но не скрывает потерю recall.

CLI возвращает 0, если отсутствуют false merges и unsupported merges в обоих
разделах. Это **только проверка безопасности объединений**: matcher, всегда
возвращающий `abstain`, пройдёт её с recall 0 и precision `null`. Успех не означает
готовность продукта, качество ранжирования или достаточную полноту каталога.
Порог recall для автоматического продвижения пока не установлен.

## Первый результат и ограничения

Первый прогон `conservative-identity-v1` 28 октября 2026 года:

- Реальные пары: 27 TP из 30 положительных, 0 false merges из 14 отрицательных,
  0 unsupported merges на 6 pending; precision 1.00, recall 0.90.
- Три пропуска: AOTY `UNLOCKED`, `SCARING THE HOES`, `SCARING THE HOES: DLC PACK`.
  В AOTY оба исполнителя записаны через `&`; в MB они отдельные artist IDs.
  Первоначальное строгое сравнение поддерживает только представление `A / B`.
- Искусственные ловушки: другое имя исполнителя при том же названии, пропущенный
  соавтор, неизвестный год при известном chart year, год переиздания, конфликт
  album/EP и edition suffix — ни одна не была ошибочно объединена.

Это целевая подборка любимых исполнителей и похожих релизов, не случайная выборка
каталога. Проценты не являются оценкой генеральной точности, доверительные
интервалы по зависимым парам не вычисляются. Нет проверки трек-листов, внешних
идентификаторов платформ для большинства пар или человеческой верификации.
Неразрешённые LP! Offline и части The Powers That B требуют дополнительных
свидетельств. Разметка не утверждает, что все варианты изданий должны иметь один ID.

Этот evaluator проверяет `classify_pair`, а не `match_releases`. Неоднозначность
между несколькими MB-кандидатами, повторные ID источника, порядок строк,
стабильность новых сущностей, сохранение provenance и запрет объединять
несовместимые дубликаты проверяются отдельными dataset-level тестами matcher.
Без них хороший результат попарного теста недостаточен.

Для следующего этапа нужны дополнительные пары других исполнителей и редких
названий, отдельная человеческая проверка спорных меток и отложенная выборка,
которую не используют для настройки правил. Изменение эталона требует новой
версии и объяснения изменения меток; улучшение matcher сравнивается на прежнем
наборе без подгонки ожидаемых ответов.
