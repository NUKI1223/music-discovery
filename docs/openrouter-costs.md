# Конфигурация OpenRouter и расходы

С 2026-10-30 локальный сайт использует GPT-5.6 Luna вместо Mistral Small 3.2.
В `.env` сохранён прежний ключ, изменены только модель и тарифы:

```dotenv
OPENROUTER_MODEL=openai/gpt-5.6-luna
OPENROUTER_INPUT_USD_PER_MILLION=0.20
OPENROUTER_OUTPUT_USD_PER_MILLION=1.20
MAX_COST_PER_REQUEST_USD=0.01
MAX_COST_PER_DAY_USD=0.10
# необязательно: дневной лимит одного аккаунта (по умолчанию равен общему)
# MAX_COST_PER_ACCOUNT_DAY_USD=0.05
```

`MAX_COST_PER_ACCOUNT_DAY_USD` не даёт одному аккаунту израсходовать общий
дневной бюджет за всех. При превышении помощник отвечает «Ваш дневной лимит
помощника исчерпан. Он обновится в 00:00 UTC.» (код `ACCOUNT_DAILY_BUDGET`).
Без переменной поведение прежнее. Резервы хранятся с `account_id`; старые строки
получают `NULL` и в лимите аккаунта не учитываются.

[Тариф модели](https://openrouter.ai/openai/gpt-5.6-luna) проверен 2026-10-30
по странице и публичному API OpenRouter: $0.20 за миллион входных и $1.20 за
миллион выходных токенов. Снимки: `artifacts/web/model-pricing.json` и
`artifacts/web/luna-endpoints.json`. Шаблон `.env.example` сохраняет нулевые
бюджеты до явного включения.

## Почему выбрана эта модель

На одном и том же коде и каталоге проверены уточнение запроса, объяснение
предыдущей карточки и неподдерживаемое условие. Во всех случаях модели вызывались
реально; повторная доставка сообщения не создавала дополнительный вызов.

| Модель | Успешные сценарии | Стоимость трёх вызовов | Время одного вызова API |
|---|---:|---:|---:|
| GPT-5.6 Luna | 3/3 | $0.0017057 | 3.6–4.1 с |
| Gemini 3.5 Flash Lite | 3/3 | $0.0024155 | 1.8–1.9 с |

Luna выбрана как более дешёвая из двух прошедших проверку моделей; Gemini в этом
прогоне быстрее. Это небольшой smoke-тест, не доказательство превосходства над
Mistral или музыкальной полезности. Отчёт: `artifacts/web/model-comparison.json`.

Дополнительно Luna прошла регрессию со старым отказом в истории: предложение
исключить знакомых исполнителей, подтверждение и сохранение исключения при
следующей неожиданной подборке. Два платных вызова стоили $0.00110155;
стандартная команда обработана локально. Отчёт: `artifacts/web/known-artists-smoke.json`.
Общий расход сравнения и регрессии — $0.00522275, в пределах отдельного общего
потолка $0.01 и действующего дневного ledger.

## Ограничения расходов

- $0.01 на сообщение, включая повторы и исправления; это потолок, не цена сообщения.
  Ответ ограничен 768 токенами, консервативный входной резерв — 8192.
- $0.10 за сутки UTC для всех аккаунтов, Streamlit и CLI через общий
  `runtime/llm-budget.sqlite3`. Смена модели не сбрасывает расход.
- В API передаются максимальные тарифы, запрет доплаты за запрос и запрет
  автоматического перехода к другому провайдеру. При отсутствии совместимого
  провайдера помощник сообщает, что недоступен, и предлагает повторить позже
  (подбор без ИИ убран 2026-11-08).
- Неизвестная стоимость сетевого сбоя остаётся зарезервированной. Если фактическая
  стоимость превышает резерв, следующие вызовы блокируются до проверки тарифов.
- Это лимит приложения, не всего аккаунта OpenRouter: другие программы и комиссии
  пополнения им не ограничиваются.

Резерв одной попытки при этих тарифах — $0.00256. Арифметический пример для
1000 входных и 200 выходных токенов — $0.00044. Фактическая стоимость берётся
из `usage.cost`; длина контекста, рассуждения модели и число попыток влияют на неё.

Кнопки оценок, история, ранжирование через фильтры, обучение и offline evals
не вызывают OpenRouter. Стандартные команды вроде «Более неожиданное» также
выполняются локально. Свободные формулировки передаются модели с текущими
фильтрами, компактной последней подборкой и максимум шестью обменами диалога.
Ключ и полный каталог в браузер не передаются.

Реальные проверки запускаются явно:

```bash
uv run python scripts/web_live_smoke.py
uv run python scripts/web_known_artists_smoke.py
```

Каждый запуск использует временную историю, общий настоящий ledger и отдельный
потолок $0.01. Предыдущие отчёты первоначальной настройки Mistral сохранены в
`artifacts/openrouter-setup/`; они не подтверждают tool-call поведение новой модели.

При смене модели необходимо одновременно проверить и обновить тарифы. После
редактирования `.env` перезапустить сервер: окружение процесса имеет приоритет.
