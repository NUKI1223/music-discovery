# Wikidata: дополнительный набор признаков

Добавлен небольшой реальный снимок структурированных данных Wikidata под [CC0](https://www.wikidata.org/wiki/Wikidata:Licensing). Он дополняет MusicBrainz независимыми утверждениями о жанре, исполнителе и дате релиза. Это метаданные, а не персональные оценки пользователя, доказательство редкости или обученная рекомендательная модель.

## Что реально получено

В `data/wikidata/raw/` сохранены запрос SPARQL, ответ поиска и ответы API с 12 сущностями альбомов и 6 зависимыми сущностями исполнителей/жанров. Последнее получение сохранённых ответов: `2026-10-28T12:10:07Z`. Состав и SHA-256 файлов перечислены в `data/wikidata/acquisition-manifest.json`.

Для исходного каталога `data/samples/musicbrainz.json` из 33 релизов найдено 12 совпадений по release-group MBID. В `data/wikidata/pilot/dataset.json` вошло 10 записей, подтверждённых также идентификаторами исполнителей. Пять записей содержат жанровые утверждения. Две записи помещены в quarantine: несколько release-group MBID у одной сущности и отсутствие MBID исполнителя. Полнота Wikidata неоднородна; эта выборка не репрезентативна для всего хип-хопа.

Для расширенного каталога `data/catalogs/musicbrainz-expanded.json` (520 релизов, таксономия `mb-tags-v2`) выполнено отдельное офлайн-пересопоставление: `data/wikidata/expanded/dataset.json`. Из 520 релизов только 27 входили в исходный запрос Wikidata; среди них найдено 12 совпадений release-group MBID, 10 подтверждённых записей, 5 записей с жанровыми признаками и 2 записи quarantine. Остальные 493 релиза не проверялись через Wikidata: отсутствие признаков у них не означает отсутствие соответствующих сущностей. Новых сетевых запросов не было, исходное время получения сохранено.

Повторный автоматизированный запрос к SPARQL получил HTTP 403. Обход ограничения не выполнялся; свежий сетевой сбор не подтверждён. Уже сохранённые ответы позволяют полностью повторить нормализацию офлайн. Каталоги `pilot/raw` и `pilot-live/raw` содержат только запросы незавершённых попыток, а исходные успешно полученные ответы находятся именно в `raw/`.

## Правила соответствия и признаки

Идентичность альбома определяется исключительно по [P436 — MusicBrainz release-group ID](https://www.wikidata.org/wiki/Property:P436). Исполнители из P175 должны подтверждаться [P434 — MusicBrainz artist ID](https://www.wikidata.org/wiki/Property:P434). Совпадение названия не используется. Неоднозначные альбомы, отсутствующие или конфликтующие идентификаторы исполнителей не присоединяются к каталогу.

[P136 — genre](https://www.wikidata.org/wiki/Property:P136) сохраняется как QID и независимый бинарный признак `wikidata_genre:Q…`. Название жанра служит только для чтения. Автоматического сопоставления с таксономией приложения нет. Например, `Q11401` не становится автоматически внутренним `hip-hop`. P577 сохраняется как исходное утверждение о времени, без подмены года в MusicBrainz.

У каждой записи есть `release_id`, `release_group_mbid`, `wikidata_id`, `artist_ids`, `genre_qids`, `genre_labels`, `features`, `mapping_status`, ревизия, URL и `claims`. В каждом claim указаны property ID, entity ID, statement ID, значение, rank и количество ссылок. Deprecated-утверждения исключены; preferred rank имеет приоритет. Общая оболочка фиксирует лицензию, время получения, snapshot/hash каталога, версию таксономии и fixture-статус.

## Воспроизводимый офлайн-запуск

Команды выполняются из корня проекта; выходной `dataset.json` не должен существовать:

```bash
.venv/bin/python -m discovery.catalog.wikidata \
  --catalog data/samples/musicbrainz.json \
  --raw-dir data/wikidata/raw \
  --fetched-at 2026-10-28T12:10:07Z \
  --output-dir artifacts/wikidata-replay

.venv/bin/python -m discovery.catalog.dataset \
  --catalog data/samples/musicbrainz.json \
  --enrichment artifacts/wikidata-replay/dataset.json \
  --output-dir artifacts/catalog-with-wikidata
```

Для нового каталога выполните нормализацию заново с его путём: snapshot/hash будут пересчитаны, а старый sidecar нельзя присоединять к другому снимку. Офлайн-повтор не расширяет охват исходного запроса и не обновляет дату получения данных. `queried_releases` учитывает только MBID, присутствовавшие в сохранённых запросах.

Сетевой режим адаптера ограничен 200 релизами, 24 запросами, 2 MB на ответ и 8 MB суммарно. Используются только официальные endpoints, пауза между запросами и User-Agent; редиректы и автоматические повторы отключены. Ошибка оставляет failure manifest и не публикует dataset. Правила доступа описаны в [Wikidata Data access](https://www.wikidata.org/wiki/Wikidata:Data_access); текущий 403 необходимо разрешить штатным способом до нового сбора.

## Использование в обучении

Совместный JSONL пригоден для анализа покрытия признаков, изучения внешней жанровой разметки и будущих экспериментов с представлениями музыки. Он не подаётся автоматически в обучение персональных предпочтений. Нет положительных/отрицательных меток пользователя, свежей популярности, аудиопризнаков и доказательства улучшения рекомендаций. Любая будущая проверка качества должна учитывать пересечение источников, временную доступность данных, повторные релизы и смещение к хорошо описанным исполнителям.

ListenBrainz MLHD+ также проверялся как кандидат: официальный endpoint вернул серверную ошибку, а [описание derived dumps](https://metabrainz.org/datasets/derived-dumps) не предоставляет CC0-лицензию для MLHD+. Его исторические агрегаты не включены и не используются как число оценок или актуальная редкость.
