## Сопоставление и provenance

`matching.json` содержит соответствие каждой исходной строки, статус, правило,
доказательства и кандидатов. Exact credit/title/known-year и явные внешние
идентификаторы обрабатываются консервативно; конфликт или несколько кандидатов
требуют отложенного решения. Alias Kanye West → Ye задан явно через MB artist ID.
Правила не являются независимым подтверждением платформенных MBID.

`pending.jsonl` сохраняет 153 неразрешённые строки вне serving-каталога. Исходные
файлы в `data/community/` не переписываются. Новым community-сущностям выдаются
локальные идентификаторы, а не вымышленные MusicBrainz ID. Прежние 520 MB ID и
датированные наблюдения сохраняются; снимки старых рекомендаций не изменяются.

`manifest.json` фиксирует состав и хеши источников, версию taxonomy, snapshot ID,
счётчики и ограничения. Исторические строки сохраняют provenance и ID источника;
недостающий RYM URL не достраивается угадыванием slug.

`artifacts/evals/unified-integrity.json` подтверждает целостность собранного
снимка; canonical SHA-256:
`b09f7dfc8c257a224a54d883dc03e1dedd0bc6f95cf58712bfec1dcc97f18f5b`.

## Жанры и исторические рейтинги

Версия taxonomy — `community-taxonomy-v1+6e4b3bae01a2`. Только сопоставленные
основные жанры и прежние жанры MB участвуют в eligibility выбранного scope.
Вторичные метки, descriptors и неизвестные labels сохраняются как отдельные
свидетельства; они не превращаются автоматически в основные жанры. Релизы без
основного жанра остаются в каталоге, но не получают выдуманный genre scope.
Результаты сопоставления меток находятся в `taxonomy.json`.

`historical_observations` хранят RYM 0–5 и AOTY 0–100 раздельно. Их дата измерения
неизвестна (`observed_at=null`), а число голосов не имеет независимо подтверждённой
семантики. Acquisition time не подставляется вместо observation time.
Эти оценки не усредняются между платформами, не участвуют в доказательстве
текущей малоизвестности и не создают личных labels. В UI они видны в отдельном
блоке с предупреждением о неизвестной дате.

Датированные наблюдения MusicBrainz остаются в `observations` и проходят прежние
проверки свежести и сопоставимости. Увеличение каталога не гарантирует достаточных
данных для строгой малоизвестности: пустой результат допустим.

## Проверка идентичности

Предварительный [entity matching reference](entity-matching-eval.md) включает 50
реальных пар и 6 отдельных синтетических ловушек. Метки просмотрены другим
coding-agent до запуска matcher; независимой человеческой верификации нет.
Первый результат — 27/30 положительных совпадений, 0 false merges на 14
отрицательных и 0 unsupported merges на 6 unresolved-парах. Три пропущенные
коллаборации с `&` показывают предел полноты первоначальных правил.

Это не population accuracy: подборка целевая, пары зависимы и относятся главным
образом к любимым исполнителям. Pending не считается ошибкой само по себе.
Проверки неоднозначности целого набора выполняются отдельно от попарного eval.

```bash
uv run python -m discovery.evals.entity_matching \
  --verify-source-root . --output artifacts/evals/entity-matching.json
```

## Использование и обучение

```bash
uv run streamlit run src/discovery/ui/app.py
uv run discovery --db runtime/cli.sqlite3 recommend --genre hip-hop
uv run discovery --db runtime/discovery.sqlite3 export-training \
  --output artifacts/training-records.json
uv run python -m discovery.training.train \
  --config configs/supervised-unified.json \
  --data artifacts/training-records.json --output artifacts/training/report.json
```

`DISCOVERY_CATALOG` переопределяет каталог. UI/CLI читают `.env` проекта;
окружение процесса имеет приоритет. Ключ не нужен для baseline. OpenRouter
требует отдельной настройки модели, тарифов и ненулевых бюджетов; в шаблоне
бюджеты равны нулю, реальные API calls при этой интеграции не выполнялись.

Новый конфиг обучения относится к новой taxonomy. Старый `configs/supervised.json`
сохранён для `mb-tags-v2`; объединять labels разных taxonomy/features в одном
training run нельзя. При смешанной истории нужно выбрать совместимый набор
реальных решений, а не переписать в нём версию. Недостаток новых личных labels
даёт `insufficient_data`, а не готовую персональную модель.

Ограничения исходных выгрузок и права распространения описаны в
[community-data.md](community-data.md). Их отбор по чартам не даёт репрезентативной
выборки малоизвестной музыки.
