# Где смотреть работу агентов

Агенты работают внутри сессии Codex, не как отдельные терминальные процессы или tmux-панели. Они используют ECC-навыки, но отдельного сервера ECC orchestration здесь нет.

Откройте отдельный терминал и запустите живую панель:

```bash
python ~/Projects/hiphop-discovery/scripts/watch_agents.py
```

Обновление каждые две секунды. `Ctrl+C` закрывает только просмотр, агенты и сборщик продолжают работу. Панель использует только стандартную библиотеку Python, читает существующие файлы и не запускает серверы, tmux, команды агентов или сетевые запросы. Работает из любой директории.

Однократная проверка:

```bash
python ~/Projects/hiphop-discovery/scripts/watch_agents.py --once
```

Роли и назначенные задачи root поддерживает в `docs/agent-tasks.json`. Это описания задач, а не вычисленные статусы исполнения; панель перечитывает реестр при обновлении. Статусы `started/complete/aborted (recorded)` отражают последнее соответствующее событие журнала. Они не доказывают, что процесс сейчас работает: агент может ждать инструмент, разрешение или новое сообщение. Завершение старой задачи не закрывает новую задачу.

Панель показывает последние события `task_started`, `task_complete`, `turn_aborted` и завершения `CommandExecution`/`FileChange`, время события, статус и числовой exit code команды, если он записан. Счётчики охватывают весь указанный журнал; `FileChange` считает события, а не отдельные изменённые файлы. Промпты, сообщения агентов, Reasoning/analysis, команды, вывод команд, пути изменённых файлов и содержимое правок не выводятся. Неизвестный exit code остаётся `unknown`.

Ниже показаны реальные поля `data/expanded/musicbrainz/state.json`: фаза, время обновления, число запросов, обработанных кандидатов и успешных lookup. Ошибки представлены количеством и категориями, без потенциально чувствительного текста. Время обновления позволяет заметить устаревшее состояние. Процент готовности не вычисляется. Отсутствующие или некорректные файлы помечаются как недоступные; незавершённая последняя JSONL-строка ожидает следующего обновления.

Формат внутренних журналов может меняться между версиями Codex. Панель проверена на перечисленных файлах; неизвестные типы событий игнорируются.

План и результат совместного ревью:

```bash
less ~/Projects/hiphop-discovery/plans/implementation.md
less ~/Projects/hiphop-discovery/docs/plan-review.md
```

Эти же три агента затем реализовали свои модули и выполнили взаимное ревью. Они запускаются повторно для исправлений; отсутствие новых событий означает, что сейчас агент не пишет в журнал. Файлы проекта общие для команды. Текущие результаты собраны в `docs/implementation-status.md`.
