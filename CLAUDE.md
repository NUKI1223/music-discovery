# Music Discovery: инструкции для Claude Code

Отвечай пользователю по-русски. Вноси изменения в этот проект только в рамках его запроса; перед правками прочитай относящиеся к задаче файлы и проверь текущие изменения.

## Проект

Это локальный сайт для поиска музыкальных релизов: React + TypeScript + Vite, FastAPI и отдельная SQLite-база на аккаунт. Каталог общий, вкусы, история, коллекция и оценки принадлежат аккаунтам. Streamlit сохранён как диагностический интерфейс. Хип-хоп — один из жанров, сайт предназначен для всех жанров.

Сначала смотри [README.md](README.md), [PROJECT-CONTEXT.md](PROJECT-CONTEXT.md) и относящиеся к задаче документы в `docs/`. В проектной истории встречаются устаревшие решения; для текущего поведения сверяйся с кодом и более поздними документами. Актуальный сбор ссылок на площадки описан в `docs/album-platforms-20261106.md`.

## Важные продуктовые правила

- Обычная отправка сообщения в чате вызывает помощника. Кнопки «Ещё варианты», «Неожиданнее» и подтверждение предложенных настроек продолжают чат.
- Подбор без ИИ убран полностью (2026-11-08): нет ни кнопки «Подобрать без ИИ», ни поля `use_llm`, ни текстов про «бесплатную подборку». Не возвращай их без прямой просьбы. Без вызова модели работают только `apply_filters=true` (подтверждение предложенных помощником настроек, «Применить и подобрать»; его же используют evals и технические скрипты) и точные команды-ярлыки вроде «Ещё варианты».
- Карточки должны показывать все найденные прямые ссылки на альбомы сразу. Не создавай ссылки поиска, профиля исполнителя или отдельного трека и не угадывай ID. Проверяй `docs/album-platforms-20261106.md` и `src/discovery/web/streaming.py`.
- Оценки «Уже знаю» и явные оценки прослушанного имеют разный смысл. Не превращай свободный текст в лайки автоматически.
- Если пользователь пишет «Рекап», разбери его последний диалог именно с музыкальным ботом сайта: запросы пользователя, ответы и подборки, обратную связь, ошибки сопоставления и фильтров. Если данных недостаточно или оценка неоднозначна, кратко спроси. Анализ не должен менять чат или базу. Подробная процедура — `/recap`.

## Данные, секреты и Git

- Не читай, не выводи, не копируй и не меняй `.env`, токены и секреты. Для настройки ориентируйся на `.env.example` и спрашивай пользователя, если конфигурации не хватает. Никогда не помещай ключ провайдера во frontend.
- `runtime/` содержит пользовательские базы, расходы и локальные данные; не очищай, не мигрируй и не переписывай их без прямой необходимости. Для тестов используй временную базу.
- `artifacts/` и `runtime/` игнорируются Git; не полагайся на них как на переносимую документацию или исходный код.
- Проект под Git с 2026-11-08 (первый коммит `442e8c2` на `main`, remote не настроен). Правки смотри через `git status` и `git diff`. Коммить и пушь только по просьбе пользователя.
- Вне Git остаются `runtime/` (пользовательские базы), `artifacts/`, `.env` и распакованные `data/unified/*/catalog.json` — в Git лежат их `catalog.json.gz`, которые читает `load_catalog`. Поэтому не запускай `git clean`, `git reset --hard` и массовый `git restore`: они не вернут игнорируемые данные.
- Не отправляй сообщения и не публикуй изменения во внешние сервисы.

## Команды

Из корня проекта:

```bash
uv run discovery-web serve
npm --prefix frontend run build
uv run pytest
uv run ruff check src tests
uv run python -m discovery.evals.run --suite release --offline --output artifacts/evals/release.json
```

Сайт: <http://127.0.0.1:8000>. Claude Code запускается командой `claude` из корня проекта. При изменениях API сверяйся с `scripts/export_web_contract.py` и frontend API-типами. Не делай платные вызовы модели для обычных проверок; используй mock и offline-сценарии. Live-проверку провайдера запускай только если она нужна задаче и укладывается в бюджет проекта.
